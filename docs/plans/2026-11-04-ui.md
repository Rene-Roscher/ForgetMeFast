## 1. Problem
- Problem: Das Krypto-Modul und die API sind ohne Oberfläche nicht benutzbar. Nutzer müssen ein Secret eingeben, einen Link bekommen und den Link mit Passwort wieder öffnen können, und sie müssen sehen können, dass nichts Geheimes den Browser verlässt.
- Personas: Ersteller (will schnell und sicher einen Link, Passwort getrennt senden); Empfänger (öffnet den Link, tippt das Passwort, liest das Secret, oft am Handy); Skeptiker (will prüfen, was gesendet wird).
- Today: Es gibt nur eine Platzhalter-Seite.
- Success moment: Der Ersteller sieht Link und Passwort als zwei getrennte Blöcke; der Empfänger sieht nach dem Passwort das Secret hinter "Anzeigen"; ein Skeptiker klappt die Server-Sicht auf und sieht exakt den gesendeten Body.
- Success metric: Playwright prüft den ganzen Weg grün: erstellen, in zweitem Kontext öffnen, Secret stimmt, dreimal falsches Passwort vernichtet, Server-Sicht gleicht dem echten Request, Klartext-Scan ohne Treffer. Kontrast der eigenen Komponenten mindestens 4,5:1 in beiden Themes (gemessen).
- Non-goals: Konten, Dateien, Mehrsprachigkeit, Statusseite für den Ersteller, Farbmarkierung (alles laut `docs/SPEC.md`).
- Stress moment: Der Empfänger tippt unter Zeitdruck auf dem Handy ein falsches Passwort. Er sieht sofort, wie viele Versuche bleiben, und das Eingabefeld behält den Fokus.

## 4. UX and states
| State | What the user sees |
|---|---|
| Empty | Leeres Eingabefeld mit Platzhalter und Hinweis "Wird im Browser verschlüsselt, bevor etwas gesendet wird"; Button gesperrt, bis Secret und gültiges Passwort da sind |
| Loading | Button zeigt "Wird verschlüsselt …" und ist gesperrt (kein Doppelabsenden); Viewer zeigt "Wird entschlüsselt …" |
| Error | Klare Meldungen je Fehlercode (kein sicherer Kontext, Passwort zu kurz, Secret zu groß, Netzwerk, gedrosselt), jede mit nächstem Schritt |
| Partial data | Link ohne Fragment: "Link unvollständig"; kaputte Serverantwort: allgemeine Fehlermeldung |
| No permission | Falsches Passwort: "Falsches Passwort, noch n Versuche" mit Fokus im Feld; nicht verfügbar: eine einheitliche Seite |
| Limit reached | Fehlversuche aufgebraucht oder Abrufe verbraucht: dieselbe "Nicht verfügbar"-Seite; Erstellen gedrosselt: Hinweis mit Wartezeit |

- Large case: Zeichenzähler zeigt Bytes von höchstens 65.532; das Eingabefeld scrollt, der Viewer zeigt langen Text in einem scrollbaren Block (höchstens etwa 90 Zeilen sichtbar).
- Mobile, keyboard and screen reader: Mobil gestapelt, Eingabefeld zuerst; alle Bedienelemente per Tastatur, Fokusring sichtbar, Beschriftungen und `aria-live` für Meldungen; Zielgrößen mindestens 24 × 24 px.
- Localisation: nur Deutsch, alle Texte in `resources/js/lang/de.ts`.
- Destructive actions and their confirmation text: "Jetzt vernichten" fragt nach: "Das Secret wird endgültig gelöscht. Der Link funktioniert danach nicht mehr." mit den Knöpfen "Endgültig vernichten" und "Abbrechen".
- Existing components reused: none (es gibt noch keine); Tokens aus `resources/css/tokens.css`.

## 14. Failure modes
| Failure | Impact | Detection | Reaction |
|---|---|---|---|
| Kein sicherer Kontext (HTTP) | Verschlüsseln unmöglich | `isCryptoAvailable()` | Seite zeigt Hinweis auf HTTPS, Eingabe gesperrt |
| Netzwerk oder Server nicht erreichbar | Anlegen oder Öffnen scheitert | `fetch` wirft | Meldung mit "Erneut versuchen"; beim Öffnen wurde kein Versuch verbraucht, solange der Proof nicht ankam |
| Entschlüsselung scheitert nach akzeptiertem Proof (`DecryptFailed`) | Secret kann schon verbraucht sein | Fehlercode | Klare Meldung: "Das Secret konnte nicht gelesen werden und ist möglicherweise verbraucht" |
| Doppelklick auf "Erstellen" | Zwei Secrets | Button gesperrt während der Arbeit | Zweiter Klick wird ignoriert |
| Clipboard verweigert | Kopieren scheitert | Promise lehnt ab | Meldung "Bitte von Hand markieren", Text bleibt markierbar |
| Seite wird nach dem Anlegen neu geladen | Link und Passwort sind weg (nur im Speicher) | nicht erkennbar | Hinweis vor dem Verlassen der Ergebnisseite; Link und Passwort sind absichtlich nicht gespeichert |

- Irreversible: Das Schließen der Ergebnisseite verwirft den Link-Key und das Verwaltungstoken endgültig, weil sie nirgends gespeichert werden.
- Costs money or reaches people if it fires wrongly: nichts.

- Cross-tenant test per new resource: N/A: Single-Tenant, keine neue Ressource.
- Failure-mode tests: je Zeile aus Abschnitt 14, soweit im Browser simulierbar (Netzwerk blockiert, Clipboard verweigert).
- Browser check: Playwright E2E mit Klartext-Scan über Datenbank, Logs und Access-Log nach Secret, Passwort und `K_link`; Server-Sicht gleicht dem echten Request; dreimal falsch vernichtet; zweiter Browserkontext öffnet; keine CSP-Verstöße; Kontrastmessung in hell und dunkel; Argon2id-Zeit unter der CSP gemessen.
